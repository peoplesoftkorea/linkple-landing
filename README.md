# Linkple — 랜딩 페이지

> **채용부터 복지까지, 사람과 일을 잇다.** 통합 HR 플랫폼 Linkple의 **컨셉 소개 랜딩 페이지**입니다.
> 코드잇 스프린트 · IT창업가 과정 **스프린트 미션 5**(창업 아이템 랜딩 페이지) 제출물.

**🔗 라이브 데모: https://linkple-landing.vercel.app**

## 개요

순수 **HTML · CSS · JavaScript**만으로 만든 정적 랜딩 페이지입니다. 기획 → 디자인 → 개발 → 배포의 전체 흐름을 담았습니다.

- **아이템**: Linkple — 채용(3자 매칭) + 임직원 복지몰(총보상)을 잇는 통합 HR 플랫폼
- **상태**: 출시 예정 서비스의 **컨셉 소개**(실제 서비스·가입·결제·중개 없음)

## 구성

| 섹션 | 내용 |
|---|---|
| Hero | 핵심 가치 · CTA |
| 문제 → 해결 | 흩어진 HR을 하나의 흐름으로 |

| 기대효과 | 타깃(HR 담당자) · 효과 |
| CTA | 출시 알림 신청(컨셉 데모) |

## 멘토 피드백 반영 (2026-08-21)

> **[Needs Work]** 컨텐츠간 간격을 조금더 고려하는게 필요해보입니다.
> **[멘토의 한마디]** 텍스트 밀도가 높아서 답답한 느낌을 줄 수 있습니다. 이는 전체 텍스트를 못 읽게 되어 랜딩페이지의 흐름이 예기치 못하게 전개될 수 있습니다.

지적을 수치로 특정해 고쳤습니다. 라틴 문자 기준으로 짠 CSS를 한글에 그대로 쓴 것이 원인이었습니다.

| 지표 | 이전 | 이후 | 근거 |
|---|---|---|---|
| 기능 카드 줄당 글자 | **13자** | **31자** | 4열 그리드를 2열로. 한글 권장 25~35자 |
| 히어로 리드 줄당 글자 | 20자 | **31자** | `max-width: 34ch` → `34em` (ch는 라틴 기준이라 한글은 절반만 들어감) |
| 본문 행간 | 1.65 | **1.75** (카드 설명 1.8) | 한글은 라틴 문자보다 넉넉한 행간이 필요 |
| 섹션 상하 여백 | 88px | **96px** | 섹션 경계를 더 분명하게 |
| 줄바꿈 | `normal` | **`word-break: keep-all`** | 한글이 어절 한가운데서 잘리던 문제 |

여백만 넓히면 문서가 길어질 뿐이라 **카피도 8곳 줄였습니다** — 히어로 리드 84→56자,
기능 설명 53→33자, 기대효과 리드 79→46자.

같은 기준을 미션 6 MVP에도 적용했습니다. → [linkple-mvp.vercel.app](https://linkple-mvp.vercel.app)

## 구현 포인트

- **시맨틱 마크업** (`header`/`main`/`section`/`footer`)
- **반응형** — 미디어 쿼리로 모바일·데스크탑 대응, 모바일 메뉴 토글
- **레이아웃** — CSS Grid / Flexbox
- **인터랙션(JS)** — 스크롤 리빌(IntersectionObserver) · 호버 효과 · CTA 모달 피드백
- **접근성** — `alt`/`aria`, 키보드 탐색, `:focus-visible`, `prefers-reduced-motion`, skip-link
- **브랜드** — Aurora Green 컬러 시스템, Pretendard 타이포그래피
- **한글 타이포** — `word-break: keep-all`, 행간 1.75, 줄당 25~35자, 문단 폭 34em
